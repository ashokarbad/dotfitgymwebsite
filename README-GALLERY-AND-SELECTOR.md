## Read this before anything else

### The build source you described was not in the zip

Your README says: *edit the source files and run `python3 build.py`, which
regenerates `site/`*. That build system is not in `files__29_.zip`. The zip
contained the compiled `site/` folder, the preview copy, the README and a
loose `index.html` — no `build.py`, no `build_lib.py`, no `content/*.json`.

So this work was done **directly on `site/`**. If you later recover the
original `build.py` and run it, it will overwrite all of it.

Pick one and stick to it:

* **`site/` is the source now.** Edit it, use the two scripts in `tools/`,
  never run the old build. This is the simpler option.
* **Recover the original source first**, then port these changes into it.
  More work, but you keep the generator that produced the 19 pages.

Do not run both.

### "Photos appear automatically when added to a folder" is not possible

A browser cannot list the contents of a folder on a web server. It can only
request files whose names it already knows. Netlify, GitHub Pages, Hostinger
and cPanel all disable directory listings by default, and where they are
enabled the output is HTML for humans, not a file list a script can read.
There is no setting that makes this work at runtime.

So the file list has to be written down somewhere. Your spec (§9) offers to
maintain that list by hand. That version rots — someone adds a photo, forgets
the data entry, and the gallery quietly misses it.

What is implemented instead is a scanner. It reads the folders and writes the
list for you:

```bash
python3 tools/scan_gallery.py
```

One command. No data file to edit, no page to edit.

## Adding photos — the whole workflow

```
1.  Put the photo in the matching folder:
        site/images/gallery/trekking/trekking-01.webp

2.  python3 tools/scan_gallery.py

3.  Upload site/
```

The photo now appears in: the gallery page, the trekking page's own gallery,
the Trekking panel on the services page, and the lightbox.

**Filenames become titles**, so name them properly. `yoga-sunrise-class-01.webp`
becomes *"Yoga sunrise class"*. `IMG_4821.jpg` becomes *"Img 4821"*.

**Categories** are the folder names under `site/images/gallery/`. To add one,
create the folder and add a line to `CATEGORIES` at the top of
`tools/scan_gallery.py`.

**Titles, dates and captions** can be set exactly with a `captions.json` inside
the folder:

```json
{
  "trekking-01.webp": {
    "title":   "Sinhagad sunrise",
    "date":    "March 2026",
    "caption": "Up before the sun, twenty-two of us."
  }
}
```

Anything not listed falls back to the filename. See
`site/images/gallery/trekking/captions.json`.

**Thumbnails** are generated automatically if Pillow is installed
(`pip install Pillow`). The grid then serves a 640px WebP and the lightbox
loads the full image only when opened. Without Pillow it still works, it just
serves full-size images in the grid — noticeably slower on mobile data. Install it.

The scanner also warns about any photo over 400 KB. Compress at squoosh.app
before adding; an uncompressed phone photo is 4–8 MB.

### Editing it

`content/services.json`, then:

```bash
python3 tools/build_sections.py
```

`key` must match a gallery folder name — that is how each panel finds its photos.

**The copy in there is a placeholder.** It is written from what each activity
is, generally. It is not written from how Dotfit runs it, because that is the
one part nobody outside the gym can write. Replace it.

### Two deliberate deviations from the spec

**Uppercase throughout, rather than sentence case that becomes uppercase on
click.** Changing `text-transform` on selection makes the text visibly jump
width. Weight, colour and the lime rule carry the state instead. The bold
state's width is also pre-measured with a hidden duplicate of the label, so
selecting an item never reflows the column.

**Grid, not masonry.** CSS `columns` fills the first column top-to-bottom, then
the second — which puts keyboard tab order and the lightbox's next/previous out
of step with what is on screen. A fixed-ratio grid keeps all three in sync.
Your §8 allows either.

## Galleries on other pages

One line of markup places a gallery anywhere:

```html
<div data-gallery="trekking" data-limit="8" data-more="gallery.html#trekking"></div>
<div data-gallery="all" data-filters="true" data-limit="24"></div>
```

| attribute | does |
|---|---|
| `data-gallery` | category folder name, or `all` |
| `data-limit` | photos before a "Show more" button (`0` = all) |
| `data-filters` | `true` adds the category pills |
| `data-cols` | override the desktop column count |
| `data-more` | link shown instead of "Show more" |

Already placed on: home, services (one per activity), gallery, training,
group-fitness, activities, trekking, DPL, fitness-challenges,
sports-performance, nutrition, sports-wear.

**Filter pills only render for categories that actually contain photos.** Your
§10 lists eighteen categories; eighteen pills is three rows on a phone, most of
them returning nothing. Empty ones stay hidden until there is something behind
them.

Categories with no photos show *"Photos coming soon"*. Opened from a local file
or `localhost`, the same box instead tells the developer which folder to fill.
Visitors never see a broken image.

## Running the scripts

From the folder containing `site/`, `tools/` and `content/`:

```bash
python3 tools/scan_gallery.py      # after adding or removing photos
python3 tools/build_sections.py    # after editing content/services.json
python3 tools/build_activities.py  # after editing content/activities.json
python3 tools/build_team.py        # after editing content/team.json
python3 tools/build_classes.py     # after editing content/classes.json
```

All five are safe to re-run. Every block they write into a page is fenced with
an HTML comment (`<!-- DOTFIT:GALLERY BEGIN -->`) and replaced in place, so a
second run updates rather than duplicates. Nothing outside those fences is
touched — your headings, copy, navigation and SEO tags are left alone.

Only `scan_gallery.py` has an optional dependency (Pillow). The others are
standard library.

## The home hero illustration

`site/assets/img/hero-training.svg` — a flat SVG of an athlete pressing a
barbell overhead, drawn only in the three logo colours. The large lime circle
behind the figure is the logo's dot at poster scale.

It is layered **underneath** the hero photo slot:

```html
<div class="hero__media hero__media--illus"
     style="background-image:var(--img-hero),url('assets/img/hero-training.svg'); ...">
```

So it shows now, while `images/hero.jpg` is missing, and the photo covers it
automatically the moment that file exists. Nothing to remove, nothing to
remember.

Two things to do **once the real hero photo is in place**:

1. Drop `hero__media--illus` from the class list in `index.html`. That modifier
   dials back the panel's dark gradient, which exists to keep the Open-now badge
   legible over a photograph and is unnecessary over the illustration.
2. Optionally remove the `url(...svg)` layer, though leaving it costs nothing —
   it is 2 KB and never renders once the photo loads.

Plain XML, no external dependencies, no embedded fonts. It stays sharp at any
size and opens in Illustrator, Figma or Inkscape if you want to change the pose
or recolour it.
